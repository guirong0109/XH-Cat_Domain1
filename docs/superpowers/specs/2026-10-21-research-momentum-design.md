# FutureReady MY — B: AI research momentum (design)

Date: 2026-10-21. Status: design and mockup approved by the user; this spec waits for review.
Mockup: https://claude.ai/artifact/6tVVn6bMvjRhW3irFeBG99 (artboard "B: AI research momentum").
Builds on: the MVP spec (2026-10-20) and the Stage 2 spec. All earlier rules still hold.

## 1. Goal

The problem statement asks for a solution that **"continuously tracks AI advancement"**. Today nothing in the app does that. B adds a dated, refreshable signal: **how fast AI-related research is growing in each skill area**, from OpenAlex. It sits next to the two signals the app already has (OpenDOSM job growth, ILO 2025 exposure).

Success: on the Radar screen a judge sees, per skill, "AI research on this skill grew X% last year (OpenAlex, fetched <date>)", presses **Refresh data**, and sees the date update or a clear fallback message.

## 2. Source and feasibility

- **OpenAlex** (`https://api.openalex.org/works`), an open research index. Data licence CC0. No key or login.
- Feasibility test on the user's PC (2026-10-21): 20 of 20 calls returned HTTP 200 in about 0.8–1.3 s each.
- **No email or personal data** is sent in any request (no `mailto` parameter). User-Agent: `FutureReadyMY/1.0`.
- **arXiv is not used.** Phrase and date-range queries returned HTTP 500 in the test. The open problem is written up in `docs/arxiv-investigation.md` for the team.

## 3. The signal

For each skill and each of the **last two full calendar years** before today (in 2026: 2024 and 2025), count OpenAlex works whose title or abstract matches:

```
"<search term>" AND ("artificial intelligence" OR "machine learning" OR "large language model")
```

with `filter=title_and_abstract.search:<that query>,publication_year:<year>` and `per-page=1&select=id`, reading `meta.count`.

- **Change** = (later − earlier) / earlier × 100, rounded to a whole percent.
- **Too few papers:** if either year has fewer than **30** papers, the skill shows no percentage. It is listed under "Too few papers to show a trend", with its two counts, and the note "That does not mean AI ignores them."
- **Rising:** a change of **25% or more** marks the skill with "↑ AI research" on the Skills in demand card.
- The current year is left out because it is incomplete.
- It counts research activity, not jobs. The UI says so.
- It **never changes the match score** or the scoring formula.

## 5. Architecture

Mirrors the OpenDOSM trend refresh (`server/trends.js`).

- **`server/research.js`** (new):
  - `readResearch(filePath)` → saved object or `null` when the file is missing.
  - `refreshResearch({ filePath, terms, fetchImpl, now })` → `{ status: 'updated' | 'failed', message, research }`.
    - `terms` = `[{ label, researchTerm }]` read from `data/skills.json`.
    - Years = `[Y − 2, Y − 1]` where `Y = now.getUTCFullYear()`.
    - Fetches 2 counts per skill, **5 requests at a time**, each with an **8 s timeout**.
    - **All or nothing:** if any call fails or returns a non-numeric count, nothing is written, the last good file is kept, and the message is `Showing research data from <date>. Live refresh failed.` (or `Live refresh failed. No saved research data yet.`).
    - **Single in-flight** per file path, like `refreshTrends`.
    - Atomic write of `data/research.json`.
- **`data/research.json`** (generated by a refresh, committed like `trends.json`):
  ```json
  {
    "source": { "name": "OpenAlex", "url": "https://openalex.org", "licence": "CC0",
                "query": "<the query template above>", "years": [2024, 2025], "fetchedAt": "<ISO time>" },
    "skills": { "<label>": { "term": "<researchTerm>", "counts": { "2024": 105, "2025": 173 } } }
  }
  ```
- **`server/app.js`**: `GET /api/data` also returns `research` (or `null`). New route `POST /api/refresh-research`.
- **`src/App.jsx`**: the existing **Refresh data** button calls both refresh routes in parallel. Each has its own status line; a failure of one never blocks the other. The re-plan notice still depends only on OpenDOSM.
- **`src/lib/research.js`** (new, pure, tested): `MIN_PAPERS = 30`, `RISING_PCT = 25`, `momentum(entry, years)` → `{ earlier, later, changePct | null, enough, rising }`, `researchRows(research)` → shown rows sorted by change (highest first, then label) plus the `tooFew` list.
- **`src/components/ResearchMomentum.jsx`** (new): the Radar card from the mockup. Bars for skills with enough papers, the "too few" box, the source line with date, and a "not loaded yet, press Refresh" state.
- **`SkillsDemand.jsx`**: "↑ AI research" on rising skills, plus a one-line key.
- **`pipeline/build_data.py`**: validates `researchTerm` on every skill and passes it through to `data/skills.json`.

## 6. Error handling

| Case | Behaviour |
|---|---|
| OpenAlex down, slow (over 8 s) or any call fails | Keep the last good `research.json`; dated "Live refresh failed" message; card still shows saved data. |
| No `research.json` yet | Card says "AI research data not loaded yet. Press Refresh data." |
| A count is 0 in the earlier year | Counts as "too few" (no division by zero). |
| Refresh pressed twice | One in-flight request is shared. |
| Hosting where files reset on restart (Replit autoscale) | Falls back to the committed `research.json`, as with `trends.json` (open item M8). |

## 7. Testing

- **Server** (`tests/research.test.js`, Vitest, mocked `fetch`):
  - success writes the file with both years, counts and `fetchedAt`
  - one failed call keeps the old file and returns the dated failure message
  - no file and a failure gives the "no saved data" message
  - two parallel calls share one refresh
  - years come from `now`
  - the request URL contains the term, the AI phrase and the year, and no email
- **Client lib** (`tests/research.test.js` or a separate file): the 30-paper minimum (either year), the 25% rising rule, an earlier count of 0, sorting and ties, the `tooFew` list, and `null` research.
- **Pipeline:** a missing or empty `researchTerm` fails the build; the term is passed through.
- **Manual:** run Refresh data on localhost; the card shows the new date. Check 360px width, reduced motion, and that the score is unchanged.
