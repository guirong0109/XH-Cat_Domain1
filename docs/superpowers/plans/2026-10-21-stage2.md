# Stage 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the ILO second opinion and the re-plan notice for real, plus three clearly labelled Stage 2 preview screens.

**Architecture:** The ILO scores enter through the existing offline pipeline (`build_data.py` adds an `ilo` field per role). The UI reads it through a pure helper in `roleView.js`. The re-plan notice compares two `rankRoles` results in a pure `replan.js`. Previews are three new hash routes with static screens; only the HR grid computes anything, using the real `skillStatus`.

**Tech Stack:** React 19 + Vite + Tailwind 4, Vitest, Express 5, Python 3 stdlib.

**Spec:** `docs/superpowers/specs/2026-10-21-stage2-design.md`

## Global Constraints

- No new npm or Python dependencies. Python pipeline: stdlib only.
- Scoring formula and factors (Moderate 0.6, Fast 1.0) unchanged; the ILO value is never used in `scoreRole`.
- Every number on screen shows its source and date. The ILO box says "our team's mapping, not an official table" and "global index, not Malaysia-specific".
- Every preview screen shows `PreviewBanner` with the text "Stage 2 preview, not working yet." Example outputs carry an "Example" badge; disabled controls say "(disabled in preview)".
- Touch targets ≥ 44px (`min-h-11`), works at 360px width, honour `prefers-reduced-motion`, colours teal `#0F766E` and orange `#C2410C`, font Plus Jakarta Sans.
- Express 5: no `'*'` routes. Do not hand-edit `data/*.json`; rebuild with `python pipeline/build_data.py`.
- No model names in code or commit messages. Commit after each task on `claude/hackathon-mvp-phase-1-dwl3nm`.
- On this Windows PC, Python HTTPS to some sites needs `SSL_CERT_FILE="C:\Program Files\Git\mingw64\etc\ssl\certs\ca-bundle.crt"`.

## Review Focus

1. A role with no ISCO mapping, or a build with no ILO file at all: the app must still load and show "No ILO match for this role." (tests in Tasks 2 and 3).
2. Refresh while the profile has fewer than 3 skills: no notice and no crash (test in Task 4).
3. Refresh where a role id exists in only one of the two rankings: `rankChanges` ignores it instead of reporting rank 0 (test in Task 4).
4. Deep link to `#preview-users` etc. with zero skills: the preview opens, it is not redirected to profile (test in Task 5).
5. HR grid when the target role `2524-02` is missing from the data: the preview says the example role is not available instead of crashing (test in Task 7).
